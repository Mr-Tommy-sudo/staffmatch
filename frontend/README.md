# StaffMatch Frontend

Мобильный веб-апп (вертикальные экраны) для MAX-мессенджера. Отдельный
рендерер: стили в `styles.css`, API-клиент в `api.js`, логика в `app.js`.

## Запуск

Статика не требует сборки — положите папку на любой статик-хостинг
(nginx, GitHub Pages, S3, MAX CDN). Это и есть origin, который нужно
указать в `CORS_ALLOWED_ORIGINS` бэкенда (через `.env`, см. корневой README).

Для локальной разработки:

```bash
# корень репозитория
cp .env.example .env
# в .env: POSTGRES_PASSWORD, MAX_BOT_TOKEN, CORS_ALLOWED_ORIGINS=http://localhost:8000
docker compose up --build
```

```bash
cd frontend
python3 -m http.server 8000
curl http://localhost:8000
```

## Авторизация

Каждый запрос к `/api/v1/**` обязан нести заголовок `X-Max-Init-Data` с
метаданными `window.WebApp.initData`. Внутри MAX-веб-приложения
`window.WebApp.initData` подставляется автоматически.

В обычном браузере открывается экран «Подключение»:

- вставьте реальную initData из MAX, либо
- нажмите «Сгенерировать для теста»: укажите `MAX_BOT_TOKEN` (тот же,
  что в `.env`) и произвольный `user id`. Код подпишет initData тем же
  алгоритмом (HMAC-SHA256), что и бэкенд, — запрос пройдёт проверку.

## Структура экранов

| Роль | Разделы |
| --- | --- |
| Гость без роли | Выбор: «Найм сотрудников» (EMPLOYER) / «Поиск работы» (CANDIDATE) |
| EMPLOYER | Вакансии (список/создание), кандидаты по матчингу, рейтинг, результаты тестов, отправка теста и приглашений |
| CANDIDATE | Профиль (навыки, формат, ЗП), назначенные тесты, приглашения и их решение |

Роль выбирается один раз (`PUT /api/v1/me/role`); сменить её невозможно
(409). Первый запрос с валидной initData создаёт пользователя без роли.

## Конфигурация

`config.js`:

```js
window.FP_CONFIG = {
  apiBase: 'http://localhost:8080',            // базовый URL бэкенда
  requireInitDataScreen: true                  // экран подключения в браузере
};
```
